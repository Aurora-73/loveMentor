# 方法论 — Wiki 主轴 + 公式辅助 + 冲突裁决 + 指标体系

## Wiki 是推理主轴（贯穿全程）

Wiki 不是"参考资料"，是分析方法论的来源。在分析过程的每个环节都应随时查阅：
- 看到 brief 信号 → 调 `wiki_context(queries, stage, focus="signals")` — 【MCP工具】批量构建知识框架
- 看到聊天模式 → 调 `wiki_context(queries, stage, focus="chat")` 找话术策略
- 看到指标数据 → 调 `wiki_context(queries, stage, focus="signals")` 解读指标
- 看到关系阶段 → 调 `wiki_context(queries, stage=阶段, focus="strategy")` 找阶段策略
- 看到公式结果 → 查 Wiki 核验而非套阈值
- 写报告时 → 查 Wiki 引用具体条目作为策略依据

推荐主入口：`wiki_context`（批量构建）。精确钻取：`wiki_search("关键词")` + `wiki_read("路径")`。

## 公式是辅助参考（核验而非套用）

- 公式数值在"数据全貌"表中出现一次
- 后续所有策略判断必须引用 Wiki 条目，不引用公式数值
- IVI=0.5 不一定比 IVI=1.1 差——结合 Wiki 知识核验
- 公式是"视角"不是"裁判"

### 公式系统

| 公式 | 含义 | 阈值（参考，不硬套） | MCP 工具 |
|------|------|-------------------|---------|
| IVI | 意图真实度 | >1.0 真实好感, <0.5 真实没戏 | `formula_calc_ivi` |
| SPE | 社交势能 | 0.8-1.5 健康, <0.6 红线阻断 | `formula_calc_spe` |
| EWS | 升温窗口期 | >0.8 出击信号, <0.3 窗口关闭 | `formula_calc_ews` |
| IS | 真实亲密度 | >0.5 高亲密度 | `formula_calc_is` |
| Gap_Effect | 情绪落差 | >0 正向, <0 负向 | `formula_calc_gap_effect` |
| EEV | 升温期望值 | >0.3 值得出击 | `formula_calc_eev` |
| CS | 矛盾状态 | >0 欲望占主导 | `formula_calc_cs` |
| action | 终极决策 | 基于 IVI+SPE+EWS | `formula_calc_action` |

**用法**：先调 `formula_get_params(name)` — 【MCP工具】获取自动参数，再代入各公式。详见 `guide('reference/formula')`

### IVI 核验示例
`formula_calc_ivi` — 【MCP工具】返回 IVI=0.5（中性区间）
- ❌ 错误：IVI=0.5 < 0.5 → "敷衍" → "建议放弃"
- ✅ 正确：读 [[IOI（兴趣指标）]] → 她最近 3 次主动分享日常 → 回复率 0.8 → 判断"窗口开放"

## 语义分析是传感器（不是第二个 Agent）

语义分析（`person_behaviors` / `behaviors_data`）是 Agent 的传感器，不是第二个 Agent。

**做什么**：
- 行为特征压缩 — 把几万条聊天记录压缩成结构化行为信号（10 维标签 + 派生指标）
- 全局辅助信号 — 提供 flirt/invitation/emotion_balance 等客观统计数据

**不做什么**：
- ❌ 不承担自然语言总结、翻译、转述
- ❌ 不输出关系结论（"她喜欢你""她讨厌你"）
- ❌ 不生成策略建议

**定位**：语义分析输出的是结构化数据，最终判断仍由 Agent + Wiki + 事实档案完成。Agent 参考 behaviors_data 但不机械套用，结合 Wiki 知识和事实档案做综合判断。

## 冲突裁决规则

Wiki 不是数据源，是**解释框架**。区分两种冲突：

- **数据源冲突**（她说了 X，历史分析说 Y）→ 按下表裁决，实时数据最高优先级
- **解释冲突**（实时数据显示回复变快，公式说窗口关闭）→ Wiki 框架决定怎么看

| 优先级 | 来源 | 说明 | MCP 工具 |
|--------|------|------|---------|
| — | Wiki/OKF 知识库 | **解释框架**：决定怎么看数据，不作为数据源参与裁决 | `wiki_context` / `wiki_read` |
| 1（最高） | 实时数据（brief/chat/metrics） | 当前事实，不可推翻 | `person_brief` / `person_chat` / `person_metrics` |
| 2 | 事实档案（evidence: note/date/events） | 客观记录，可信 | `person_evidence` / `person_note` / `person_date` / `events_save` |
| 3 | 事件检测（events） | 从数据推导，基本可信 | `events_scan` / `events_save` |
| 4 | 公式计算（formula_*） | 量化视角，有启发但需核验 | `formula_calc_*` |
| 5（最低） | 历史分析（data/outputs/analysis/） | 过去的观点，可能已过时 | `person_compare` |

**核心原则**：Wiki 决定怎么看，实时数据决定发生了什么。两者不冲突时不裁决；冲突时以实时数据为准（例如 Wiki 说这个阶段回复率应该低，但她实际回复率 0.9 → 她 0.9 才是事实，Wiki 框架需要在这个案例上修正应用方式）。

## 分析原则

1. **Wiki 先行**：先读 Wiki 找方法论框架，再看数据，最后用公式核验
2. **区分层次**：事实（她说了什么）→ 推断（她可能什么意思）→ 建议（你应该怎么做）
3. **引用来源**：分析中引用 Wiki 框架时，标注 `[[条目名]]` 来源
4. **不要泛泛而谈**：每个建议必须具体到"说什么话""去哪里""什么时候"
5. **注意个人模式**：brief 中的"个人模式警告"要纳入分析
6. **公式只出现一次**：IVI/SPE 等数值只在数据全貌表出现，不主导策略分发

## 指标体系速查

15 个有效加权指标 + 1 个旧版兼容指标（qscore 权重为 0）+ signal_flags + media_engagement。通过 `person_metrics(name)` — 【MCP工具】或 `person_status(name)` — 【MCP工具】获取。

| 指标 | 含义 | 权重 |
|------|------|------|
| fback | 回复字数比（她/你） | 0.10 |
| rlatency | 回复速度比（你/她） | 0.10 |
| fback_quality | 回复质量（正向情绪+追问-敷衍） | 0.10 |
| qscore_personal | 个人化问题比例（IOI） | 0.10 |
| trend | composite 周变化 | 0.10 |
| escore_volatility | 情绪波动（会话间标准差） | 0.08 |
| moments | 朋友圈互动频率 | 0.06 |
| qscore_functional | 工具化问题比例（供养者信号） | 0.05 |
| rlatency_context | 慢回时有解释的比例 | 0.05 |
| msg_volume_trend | 消息量周变化率 | 0.05 |
| latency_trend | 回复速度周变化率 | 0.05 |
| recent | 最后消息距今天数 | 0.05 |
| active_days | 活跃天数（30 天窗口） | 0.04 |
| escore | 情绪表达比例 | 0.05 |
| msg_count | 消息总数（对数归一化） | 0.02 |

**乘法惩罚**：neediness_penalty（0.4-1.0），消息量比>2 或发起频率>70% 时触发。
**信号等级**：强窗口(≥0.70) / 中窗口(≥0.50) / 弱窗口(≥0.30) / 冷淡(≥0.15) / 无信号(<0.15)
**互动模式**：lover / provider / neutral（通过 `person_status` 查看）

## 关系阶段（9 个）

| 阶段 | 特征 |
|------|------|
| **初识** | 刚认识，礼貌性回复，话题浅层 |
| **有基本互动** | 有来有回但停留在表面 |
| **高频聊天** | 经常聊天，主动分享日常，回复快 |
| **已约见** | 已经线下见过面 |
| **持续接触** | 见面后继续保持联系 |
| **暧昧推进** | 明确好感信号：主动、撒娇、吃醋 |
| **关系确认** | 已确认恋爱关系 |
| **冷淡/停滞** | 兴趣下降：回复变短、不再主动 |
| **退出/失败** | 基本不再联系，或明确拒绝 |

## Wiki 知识库

覆盖 entity（概念/框架）、topic（主题综述）、synthesis（跨源对比）、scenario（场景决策页）四类页面。

**场景决策页**：她不回消息了、她忽冷忽热、被发好人卡、吵架冷战怎么修复、什么时候该止损、如何拉升关系、如何走出友谊区、第一次约会怎么安排、确定关系后怎么维护...

**核心框架**：IOI/IOD、关系三要素、70%频率法则、供养者vs情人、需求感控制、窗口识别

**Wiki 检索 fallback 策略**（无匹配时）：
| 情况 | Agent 行为 |
|------|-----------|
| 搜索结果为空 | 凭通用社交经验判断，告知用户"Wiki 缺少关于 XX 的条目" |
| 低分命中 | 内容仅供参考，结合事实档案和实时数据独立判断 |
| 关键词未命中 | 用同义词重试（"推拉"→"推拉节奏"→"欲擒故纵"→"情绪波动"） |
