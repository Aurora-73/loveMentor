# Signals 信号解读

## 概述

`signals/` 存放 Agent 的**信号解读规则**，定义如何识别和解读聊天中的各种信号（IOI、冷落、窗口、需求感、操控等）。这些规则是 Agent 分析关系状态的重要依据。

## 信号分类

### 基础信号（basic_signals.md）

| 信号类型 | 说明 | 检测方法 |
|----------|------|---------|
| IOI（兴趣指标） | 对方表达兴趣的信号 | 关键词匹配、回复质量分析 |
| 冷落信号 | 对方兴趣下降的信号 | 回复速度变慢、回复字数减少 |
| 窗口信号 | 对方处于可推进状态 | 综合指标评估（强窗口/中窗口/弱窗口） |
| 需求感信号 | 用户自身需求感过高的信号 | 消息量比、发起频率 |
| 互动模式 | 当前互动类型 | lover/provider/neutral |

### 操控信号（manipulation_signals.md）

| 信号类型 | 说明 | 识别方法 |
|----------|------|---------|
| 废物测试 | 对方测试你的框架 | 提问方式分析 |
| 框架操控 | 对方试图建立主导地位 | 话题控制分析 |
| 情绪操控 | 对方试图影响你的情绪 | 情绪波动分析 |

## 信号等级

| 等级 | 阈值（composite） | 含义 | 策略建议 |
|------|------------------|------|---------|
| 强窗口 | >= 0.70 | 强烈兴趣信号 | 可以推进关系 |
| 中窗口 | >= 0.50 | 中等兴趣信号 | 保持互动，寻找推进机会 |
| 弱窗口 | >= 0.30 | 微弱兴趣信号 | 谨慎推进，不要急于表白 |
| 冷淡 | >= 0.15 | 冷淡状态 | 减少联系频率，重新评估 |
| 无信号 | < 0.15 | 无兴趣 | 考虑放弃或重置 |

## 互动模式

| 模式 | 特征 | 策略建议 |
|------|------|---------|
| lover | 高回复质量、高个人化问题、低需求感 | 正常推进 |
| provider | 高工具化问题、低个人化问题 | 警惕供养者模式，提升框架 |
| neutral | 中等各项指标 | 观察一段时间 |

## 需求感惩罚

当用户需求感过高时，系统会应用乘法惩罚：

```
neediness_penalty = 0.4 ~ 1.0
触发条件：消息量比 > 2 或发起频率 > 70%
最终 composite = 原始 composite × neediness_penalty
```

## 动态信号

系统会检测最近一段时间内的信号变化：

| 信号类型 | 说明 |
|----------|------|
| 上升信号 | 指标近期呈上升趋势 |
| 下降信号 | 指标近期呈下降趋势 |
| 波动信号 | 指标近期波动较大 |
| 稳定信号 | 指标近期保持稳定 |

## 信号解读流程

```
1. 获取指标数据（person_metrics）
2. 根据 composite 确定信号等级
3. 根据互动模式确定当前状态
4. 检测需求感惩罚
5. 识别动态信号
6. 查询 Wiki 获取策略建议（wiki_context）
7. 综合分析给出结论
```
