# Metrics 指标体系

## 概述

`metrics/` 存放 Agent 的**指标体系定义**，包括 15 维加权指标、乘法惩罚、信号等级划分等。指标体系将非结构化的聊天记录压缩为 LLM 可消化的结构化特征向量。

## 15维有效加权指标

| 指标 | 含义 | 计算方式 | 权重 | 范围 |
|------|------|---------|------|------|
| fback | 回复字数比（她/你） | 对方回复字数总和 / 你的发送字数总和 | 0.10 | 0-3 |
| rlatency | 回复速度比（你/她） | 你的平均回复时间 / 对方平均回复时间 | 0.10 | 0-5 |
| fback_quality | 回复质量 | 正向情绪 + 追问 - 敷衍 | 0.10 | -0.5~1.0 |
| qscore_personal | 个人化问题比例 | 个人化问题数量 / 总问题数量 | 0.10 | 0-1 |
| trend | composite 周变化 | 本周 composite - 上周 composite | 0.10 | -0.5~0.5 |
| escore_volatility | 情绪波动 | 会话间情绪评分标准差 | 0.08 | 0-1 |
| moments | 朋友圈互动频率 | 朋友圈互动次数 / 消息总数 | 0.06 | 0-1 |
| qscore_functional | 工具化问题比例 | 工具化问题数量 / 总问题数量 | 0.05 | 0-1 |
| rlatency_context | 慢回时有解释的比例 | 慢回时有解释的次数 / 慢回总次数 | 0.05 | 0-1 |
| msg_volume_trend | 消息量周变化率 | 本周消息量 / 上周消息量 | 0.05 | 0-2 |
| latency_trend | 回复速度周变化率 | 本周平均回复时间 / 上周平均回复时间 | 0.05 | 0-2 |
| recent | 最后消息距今天数 | 今天 - 最后消息日期 | 0.05 | 0-90 |
| active_days | 活跃天数 | 30天窗口内有消息的天数 | 0.04 | 0-30 |
| escore | 情绪表达比例 | 情绪表达语句数 / 总语句数 | 0.05 | 0-1 |
| msg_count | 消息总数（对数归一化） | log10(消息总数 + 1) | 0.02 | 0-5 |

## 乘法惩罚

需求感惩罚（neediness_penalty）：

```python
if 消息量比 > 2 或 发起频率 > 70%:
    neediness_penalty = max(0.4, 1.0 - (消息量比 - 2) * 0.2)
else:
    neediness_penalty = 1.0

最终 composite = 原始 composite × neediness_penalty
```

## 信号等级划分

| 等级 | 阈值（composite） | 含义 |
|------|------------------|------|
| 强窗口 | >= 0.70 | 强烈兴趣信号 |
| 中窗口 | >= 0.50 | 中等兴趣信号 |
| 弱窗口 | >= 0.30 | 微弱兴趣信号 |
| 冷淡 | >= 0.15 | 冷淡状态 |
| 无信号 | < 0.15 | 无兴趣 |

## 互动模式

| 模式 | fback | qscore_personal | qscore_functional | 特征描述 |
|------|-------|-----------------|-------------------|---------|
| lover | > 0.8 | > 0.3 | < 0.3 | 高回复质量、高个人化问题 |
| provider | > 0.8 | < 0.3 | > 0.3 | 高回复但工具化问题多 |
| neutral | 其他 | 其他 | 其他 | 中等各项指标 |

## 动态信号

| 信号类型 | 检测条件 | 说明 |
|----------|---------|------|
| 上升信号 | trend > 0.1 | 指标近期呈上升趋势 |
| 下降信号 | trend < -0.1 | 指标近期呈下降趋势 |
| 波动信号 | escore_volatility > 0.3 | 情绪波动较大 |
| 稳定信号 | abs(trend) < 0.05 | 指标保持稳定 |

## 指标计算流程

```
1. 查询消息数据（最近90天）
2. 计算各维度指标
3. 应用权重求和得到原始 composite
4. 计算 neediness_penalty
5. 应用惩罚得到最终 composite
6. 确定信号等级和互动模式
7. 检测动态信号
8. 返回完整指标数据
```

## 设计原则

1. **数据驱动**：所有指标基于客观数据计算，不包含主观判断
2. **可解释性**：每个指标都有明确的计算方式和含义
3. **权重可调**：通过 config.yaml 调整各指标权重
4. **需求感惩罚**：防止用户因需求感过高而误判关系状态
5. **时间窗口**：默认使用最近90天的数据
