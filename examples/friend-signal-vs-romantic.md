# 案例：朋友信号 ≠ 浪漫信号——高质量聊天为什么仍可能不推进

> 完全合成的教学案例。内容提取自多种互动模式的共同结构，人物、专业、地点和措辞均为重新写作。

## 问题

用户和小遥在共同兴趣群认识。小遥会点赞动态，也会在准备面试、选设备或处理技术问题时来问意见；两人聊天轻松，偶尔聊到很晚。几周后，互动仍集中在“有事才找你”：小遥很少反问用户的生活，也没有把对话带向共同体验。

友好不是低价值信号，但不能自动等于浪漫兴趣。

## 脱敏后的互动切片

| 场景 | 重新写作后的片段 | 更稳妥的解读 |
|---|---|---|
| 公域互动 | 小遥：“这个路线看起来不错。” | 低成本友好，不能单独推出亲密兴趣 |
| 功能性私聊 | 小遥：“你上次说的工具怎么配置？” | 有信任感，对话目标仍是解决问题 |
| 用户转场 | 用户：“周末去 xx 公园附近看小展，要不要一起？” | 一次合适、低压力的验证 |
| 对方反馈 | 小遥：“最近先赶进度，之后有需要再问你。” | 没有接受，也没有替代时间；关系回到功能轨道 |

## 信号分层

| 信号层 | 证据 | 不能推出什么 |
|---|---|---|
| 公域友好 | 点赞、评论、群聊接话 | 正在经营一对一亲密关系 |
| 功能性投入 | 主动咨询、感谢、认可能力 | 想从问题转向约会 |
| 私人化投入 | 无任务时来聊天、主动追问近况 | 一次出现就足以证明意图 |
| 行动投入 | 愿意共同确认时间、调整安排 | 一次拒绝就意味着永远没有可能 |

## 系统如何避免误判

`friendzone_risk` 是提醒“互动是否长期由功能需求驱动”，不是对关系的判决。模型把提问识别为行为，却不会把每个问题都自动加到浪漫兴趣；问题对象、上下文和后续行动同样重要。事实档案则记录有没有发生过一对一、可落实的共同安排。

可以在问题结束后换一个不以帮忙为前提的场景：

> “那个问题终于处理完了。周末我会去 xx 公园附近看小展，如果你有空，可以一起逛一小时；不方便就下次群里见。”

| 反馈 | 更新方式 |
|---|---|
| 接受并共同确认细节 | 记录一次行动投入，观察是否自然延续 |
| 拒绝但主动给替代方案 | 保留开放判断，等对方给出的窗口 |
| 含糊带过并回到求助主题 | 不再把功能性联系解读成窗口 |
| 明确只想做朋友 | 直接接受边界 |

## 案例要点

- 高质量交流可能是友谊，也可能是开始；数据不能跳过中间的行动验证。
- 共同落实一件小事，通常比“聊天愉快”更接近推进信号。
- 系统减少过度解读，不把友好互动变成压力。
