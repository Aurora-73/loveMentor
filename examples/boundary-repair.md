# 案例：冲突修复——先处理边界，再谈升温

> 合成示例。人物、对话、时间和指标均为改写或示意值。

## 场景

指标显示双方仍有稳定互动，关系也处在较近阶段；但对话中出现了明确的边界表达。用户继续解释自己的动机，并尝试用浪漫话题把氛围拉回去，冲突反而变得更大。

## 为什么指标不能单独决策

| 层级 | 发现 | 优先级 |
|---|---|---:|
| 统计指标 | 回复仍然持续，互动量不低 | 参考 |
| 语义指标 | 亲密/情绪信号仍存在 | 参考 |
| 事实档案 | 对方明确提出具体边界 | 高 |
| 事件检测 | 最近发生冲突，且尚未闭环 | 高 |

## 推理链

1. “还在回复”只能说明连接尚未断开，不能抵消边界表达。
2. 升温公式衡量的是推进时机，不负责判断冲突是否已修复。
3. 修复目标应该是让对方能预测用户接下来会怎么做，而不是证明用户的解释正确。
4. 具体行为承诺完成后，再观察关系是否恢复；不要用连续独白逼迫对方立即确认。

## 输出建议

> 先用一句清晰的话承认边界，再给出一个可执行的行为承诺；停止追加论证，留出反馈空间。只有在边界被尊重、互动自然恢复后，才重新评估是否适合升温。

## 这个案例展示了什么

- 事实层优先于历史分析和单次模型分数。
- Agent 会解释公式的适用边界，而不是机械执行阈值。
- “修复”与“推进”是两个不同工作流，不能因为窗口存在就跳过前者。
